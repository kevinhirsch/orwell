# 0012 — Conversation & scene system

> **Status:** Draft. **The player's moment-to-moment interface** — the social game, where the
> #1 mandate (behavioral fidelity) meets the player. **Interaction model (decided): hybrid** —
> free-text for social play, explicit validated prompts for binding decisions.
> **Executable spec:** [`0012-conversation-and-scene-system.feature`](./0012-conversation-and-scene-system.feature)

## 1. Summary

The player moves through the house and plays the **social game in natural language**: they
address any houseguest or describe an approach; the **LLM voices NPCs and narrates**; NPCs also
**initiate** scenes per their own agendas and relationships. The **engine owns ground truth**
(relationships, knowledge, outcomes) — the LLM voices, it never decides. Every scene becomes an
**event** with a witness set. Binding game decisions are **explicit, validated prompts**, not
parsed from prose. It all runs over the **MCP boundary (0009)** and behind the **Vault Wall**.

## 2. Scope

**In:** free-text **bidirectional** scene initiation (player ↔ NPC); **social reads**; the
**hybrid** decision prompts; **player-directed scene fidelity** (compressed beats vs full
scenes); recording scenes as events with witness sets.

**Out:** the weekly loop/phases (**0011**); the LLM adapter internals (`NarrativePort` / **0009**);
the relationship math (**decision 0002**); the Diary Room (**0013**); off-screen NPC-to-NPC scene
*generation* (**0003**, surfaced here only via gossip/social reads).

## 3. The hybrid model

- **Free-text social.** The player types what they say/do. The engine assembles the Vault-free
  `NarrationContext` (0009 `renderScene`); the LLM replies in the NPC's voice + narration. The
  scene is recorded via `recordInteraction` as an event whose **witness set includes the player**
  → it is the **player's knowledge, not secret** (0002).
- **Explicit decisions.** When the loop (0011) has a pending **player** decision (nominate,
  use/replace veto, vote), the surface presents it as an **explicit prompt over the legal option
  set** and submits it for **validation against 0005** — never inferred from conversation. A
  houseguest can be *lobbied* in free-text, but the binding choice is an explicit act.

## 4. Bidirectional initiation

Both sides start scenes. The player approaches anyone; and the engine/scheduler **surfaces
NPC-initiated approaches** driven by the NPC's profile, agenda, and relationship reads + the
per-moment temperature roll (spec §10). Neither side initiates everything — the player should
never feel like the only engine moving the social game.

## 5. Social reads

"What's the energy in the room?" / "what vibe am I getting from this houseguest?" is a
first-class query returning an **honest, character-appropriate read** — sourced **only** from the
player's visible projection and the relationship reads the player could plausibly perceive. It
may **hint** at off-screen shifts (the effects of gossip diffusion, 0002) **without naming**
them, and it **never** contains Vault data.

## 6. Vault Wall & anti-sycophancy (the hard constraints)

- Everything the player sees comes from the **visible projection** (0001/0009) — no Vault.
- **NPC dialogue is constrained to what that NPC legitimately knows** (0002): the LLM may not
  voice a fact the NPC has no in-game pathway to (it can *suspect*, never *know* it).
- **The engine decides; the LLM voices.** Outcomes, who-knows-what, and relationship truth are
  engine-owned and **queried**, never bent to please the player.

## 7. Recording

Each scene → an `EventStore` event `{ initiator, witnessSet, content, ts }`. Player-present →
player knowledge (0002). NPC-initiated scenes the player is **absent** for are off-screen/hidden
(generated by 0003) and reach the player only via a pathway.

## 8. Contracts (grounded in the built 0009 tools)

```
# reads / narration (already built)
getVisibleStateFor(player) -> VisibleState
renderScene(mode) -> narration            # from the Vault-free NarrationContext
socialRead(target?) -> read               # honest, Vault-free; may hint, never names off-screen facts
# actions
recordInteraction(initiator, witnessSet, content) -> { eventId }   # the scene event
# explicit decisions (hybrid) — via the loop
pendingDecision(state) -> { phase, owner, legalOptions } | none    # 0011
submitDecision(choice) -> ok | rejected(reason)                    # validated vs 0005; never from prose
```

`socialRead` is a new player tool (allowlist, `readsVault: false`); it joins the 0009 registry.

## 9. Test strategy

- A player-initiated scene records an event whose witness set **includes the player**; it is
  **not** secret (cross-checks 0002).
- An NPC **initiates** a scene with the player over a seeded stretch (bidirectional).
- A **social read** returns **no Vault sentinel** and names no off-screen event (extends the 0001
  sentinel test to this tool).
- NPC dialogue never asserts a fact the NPC has **no pathway** to (cross-checks 0002).
- A binding decision is captured **only** via `submitDecision` and **rejected** if illegal
  (cross-checks 0005); free-text lobbying does **not** mutate the binding choice.
- Scene **fidelity is player-directed** (compressed vs full) and does not change ground truth.

## 10. Definition of Done

- [ ] Free-text scenes (both directions) record correctly-witnessed events; player-present scenes
      are player knowledge, never Vault.
- [ ] Social reads + all narration prove **Vault-free** (sentinel) and respect NPC knowledge limits.
- [ ] Binding decisions go only through validated explicit prompts; illegal choices rejected.
- [ ] NPCs demonstrably initiate (bidirectional), driven by relationships + temperature.
- [ ] Everything flows over the MCP boundary (0009); no outward path reads the Vault.

## 11. Dependencies

(decision points), decision 0002 (relationship reads). **Feeds** the odysseus front-end/agent
(the chat surface) and is the heart of the player MVP.
