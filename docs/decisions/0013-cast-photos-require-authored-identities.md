# 0013 — Cast photos require a model-authored identity (no authoring → no photo)

> **Status:** **Accepted — built (2026-06-21).** Implemented FE-side in the portrait warm
> (`frontend/src/orwell_prewarm.py`): a face is generated ONLY when its houseguest's own authoring
> gate has fired (a real model write-back via `_on_authored`); the whole-cast `_on_done` no longer
> force-opens un-fired per-NPC gates, and `_shoot_one` shoots iff its NPC's gate is set (never on a
> whole-cast-done fallback, never on a pure timeout). The portrait **backfill** shoots a late-authored
> NPC if/when its authoring lands. Gate: `frontend/tests/test_adr0013_photo_requires_authoring.py`
> (+ the updated `test_0065_cast_prewarm.py` cases).
> **Source:** Owner ruling, 2026-06-21 — *"a photo should always have a model-authored NPC, otherwise
> no photo. Photos must always match prewarmed identities; if we feed photos too early before
> identities are written, they are inconsistent with the text later."* Surfaced while auditing the
> season→new-season prewarm carry (see `UX-AUDIT-LOG.md` R6-01…R6-04).
> **Builds on:** feature 0065 (cast pre-warm: the Phase-1 identity/author warm + the Phase-2 portrait
> warm + the per-NPC authoring gates #7), feature 0058 (deep character profiles), feature 0051
> (in-character images / the FE-owned image provider).
> **Inherits / bounded by:** the Vault Wall (mandate #2 — the warm reads only the Vault-free roster),
> non-degradation (mandate #4 — a face never regresses to a thin/seeded likeness), and
> behavioral-fidelity (mandate #1 — the player's first read of a houseguest, their face, must match
> the character they will actually meet).

## Context

A houseguest exists in two depths:

- the **seeded floor** — the engine's deterministic cast (names + basic facets), generated WITHOUT a
  model; and
- the **model-authored identity** — the deep profile the FE authors via the LLM and writes back to the
  store (`recordCastProfile` / the next-season holding store).

Portraits are generated by the FE (0051) from a Vault-free prompt built off the houseguest's facets.
The portrait warm (0065) is **gated** on authoring: per-NPC gates (#7) hold each face until that
houseguest's authoring write-back lands, so faces stream in as they are authored — *"never before a
character is authored."*

Two **fallbacks** in the prior implementation could nonetheless emit a face for an identity that was
**not** model-authored:

1. **The whole-cast `_on_done` fallback.** When authoring finished (success OR failure), `_on_done`
   force-opened *every* per-NPC gate that had never fired — so an NPC the model couldn't author shot
   its face anyway, **from the seeded floor**.
2. **The per-NPC timeout.** `_shoot_one` waited on the gate with `_AUTHOR_WARM_TIMEOUT` (15 min) and,
   on timeout, **shot anyway** ("re-shoot backstop covers a later store change").

Both prioritised *liveness* ("always show a face") over *consistency*. But a face shot from the seeded
floor — or from a mid-write store — is a likeness of an identity the player has **not** been given. When
the deep authoring later lands (richer ethnicity / age / presentation / demeanour), the already-shown
face can contradict the text. **The face is the player's first and most durable read of a houseguest;
a face that doesn't match the character is a behavioral-fidelity and non-degradation failure.**

A note on impossibility (the framing that prompted this ADR): you cannot warm a season's photos
*before* that season's identities — a photo is a function of the authored identity. Photos are
therefore **strictly downstream** of authoring, never parallel to it and never ahead of it.

## Decision

**A cast photo is generated only from a model-authored identity. No model-authoring for a houseguest
⇒ no photo for that houseguest** (a placeholder stands until authoring lands). Concretely:

1. A face shoots **iff** its houseguest's own per-NPC authoring gate has fired (`_on_authored(hid)` —
   a real deep-profile write-back).
2. `_on_done` (whole-cast authoring finished, success or failure) releases **only** the whole-cast
   fallback gate. It **no longer force-opens** un-fired per-NPC gates — an un-authored NPC is left
   without a face, deliberately.
3. `_shoot_one` for a per-NPC prompt races its gate against whole-cast-done and shoots **only if its
   own gate is set**. On a total authoring hang (the timeout), it **does not shoot** — no photo beats a
   mismatched one. (An id-less prompt, which has no per-NPC signal, keeps the whole-cast gate but still
   never shoots on a pure timeout.)
4. A houseguest authored **late** (after whole-cast-done, or after a transient failure) gets its face
   from the existing **portrait backfill / re-shoot** path once its authored profile is in the store —
   so "no photo now" is never "no photo ever" for an identity that does eventually get authored.

This holds for both warm paths: first-season casting (`prewarm_cast` / `warm_portraits`) and the
season→new-season prewarm (`warm_next_season`), whose finale-day Phase-1 identity warm is adopted by
the cutover, with Phase-2 portraits then shooting off the adopted, authored identities.

## Consequences

- **Consistency is absolute:** a player never sees a face that contradicts the houseguest's authored
  text. Photos always match prewarmed identities (the invariant the owner stated).
- **Liveness is preserved without lying:** un-authored / hung NPCs show the cast **placeholder**
  (the existing silhouette avatar), and the backfill fills the real face once authoring lands — rather
  than a wrong face that must be visibly corrected later (which non-degradation forbids).
- **The 15-minute `_AUTHOR_WARM_TIMEOUT` no longer emits a face.** It now bounds only how long a
  `_shoot_one` task waits before exiting *without* shooting (liveness for the task, not a photo).
- **No model at all** (no provider configured): author warm never starts ⇒ `warm_portraits` declines ⇒
  `createCharacter`'s own portrait fallback owns that degenerate path unchanged (a no-model deploy has
  no narration either; out of scope for this ADR).
- **Behavior change to a shipped path:** this overturns the prior 0065/#7 "whole-cast fallback shoots
  an un-authored NPC from the seeded floor" behavior; the test that pinned it
  (`test_portraits_whole_cast_fallback_shoots_an_unauthored_npc_at_authoring_end`) is replaced by its
  inverse (`…unauthored_npc_gets_NO_face…`).

## Testability

- `test_adr0013_photo_requires_authoring.py`: authored NPCs shoot; an un-authored NPC (gate never
  fired, whole-cast done) does NOT; nothing-authored ⇒ zero photos; no-author-warm ⇒ decline.
- `test_0065_cast_prewarm.py`: the per-NPC gating cases + the new "unauthored ⇒ no face" case.

## Addendum (2026-07-13) — the LAZY seams, the prompt CONTENT, and the staleness self-heal

The owner reported live portraits that "don't match people's storylines or aesthetics." The audit
found the 2026-06-21 decision held at the *warm/createCharacter* seams but leaked at three others,
all now closed (FE: `orwell_portraits.py` / `orwell_prewarm.py` / `orwell_cast_authoring.py`;
engine: `portraitPrompts.ts` / `GameSessionAdapter.getPortraitPrompt`):

1. **The lazy seams shot un-authored faces.** The G9 roster backfill, the manual lever, and the G20
   reconciler generated ANY missing face regardless of authoring — so when authoring landed late
   (or was floored for hours), the whole cast shot from the pre-authoring seeded floor.
   `adr0013_allowed_ids` now filters the ONE funnel (`backfill_missing`) with the same fork as the
   #1313 house-entry gate: an authoring model resolves ⇒ an ACTIVE NPC shoots only once its deep
   profile is AUTHORED (the engine's Vault-free per-card flag); no model ⇒ the floor is the final
   cast and everything passes (fail-open). Pre-game passes (the per-NPC warm gates own it there).
2. **The gated warm shot the right TIME but a stale PROMPT.** `_shoot_one` shot the prompt entry
   captured at pre-seed time — which predates the very write-back that opened the gate. The per-NPC
   authored shoot now goes through `kickoff_authored_reshoot`, which re-fetches the CURRENT prompt
   via `getPortraitPrompt` (extended to serve the warmed pre-seed store pre-game), so the face is
   shot from the store AS IT STANDS at shoot time.
3. **No self-heal for a face that predates its authored identity.** A stale face on disk was never
   re-entered into the pipeline (`missing_portrait_ids` only lists face-less subjects). Two healers
   now exist: the LATE-authoring seam (`backfill_unauthored` wires `on_authored` → the per-NPC
   re-shoot, which DISCARDS a fingerprint-mismatched face first — the wrong face must never carry
   as an img2img identity reference — then regenerates from the authored prompt), and the G20
   reconciler's **staleness pass** (`_heal_stale_authored_faces`: active + authored + fingerprinted
   face whose stored 0065 prompt fingerprint differs from the current prompt's ⇒ discard +
   re-shoot), capped at `STALE_RESHOOT_PER_SWEEP` (= the `IMAGE_BUDGET.perTurnCap` mirror) per
   sweep with a per-user authored-count watermark, so an existing season heals over a few sweeps
   without flooding the provider.

Separately, the prompt now also *carries the storyline*: `portraitPrompts.ts` consumes the PUBLIC
authored facets `identityConcept` (0116 freeform identity) and `vocation` (L28/0058) — both already
on the HouseguestCard — as `Character:` / `Occupation:` clauses ahead of the season anchor, so
wardrobe/grooming/attitude match who the person actually is. Absent facets ⇒ byte-identical prompt.
Gates: `frontend/tests/test_adr0013_backfill_gate.py`, the updated
`test_adr0013_photo_requires_authoring.py` / `test_0065_cast_prewarm.py` /
`test_cast_authoring_backfill.py`, and `tests/unit/portraitPrompts.test.ts` (the storyline-facet +
pre-game fresh-fetch + sentinel cases).
