| 0018 | [Engine event-push / the "living house"](./0018-engine-event-push-living-house.md) | **Proposed** (owner-elected, 2026-07-09). The **game-design** ADR that 0017 punts to: whether — and on what **activity signal** — the engine may **originate** beats (NPCs act between the player's turns; the house pushes a beat) rather than only advancing on the player's own turn. **Owner correction (verbatim):** *an open socket is NOT a presence/activity signal* — a background tab / pocketed phone holds one; "actively playing" = the player **taking turns**. So engine push may never key off socket-open, only an explicit activity signal. Lays out three options — **A** status quo (turn-only; today's per-turn off-screen tick), **B** a bounded in-session activity window (turn-recency + FE foreground assertion + per-window budget; **recommended, off by default**, a *refinement* of the 2026-06-10 ruling), **C** wall-clock living house (**rejected** — the structural-disadvantage reversal the ruling closed). Invariants held regardless: the 0065 `beatSeq`/409 closed-set spine authoritative (a pushed beat is a committed mutation, not narration), the Vault Wall (mandate #2), cross-user isolation (0021), anti-sycophancy (seeded engine outcomes). Delivery (0017's socket) ≠ licence. Open red-lines: build B vs stay A; the exact signal + bounds. |
