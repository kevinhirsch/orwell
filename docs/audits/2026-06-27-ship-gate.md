# Ship gate — the launch-acceptance bar (2026-06-27)

**Purpose.** Stop discovering-and-polishing into infinity. This document defines what
"shippable" means for Orwell, so we can draw a hard line: a finite set of **launch-blockers**,
everything else explicitly **post-launch** or **parked**. It is the overseer's authoritative
launch checklist; pair it with the issue triage at the bottom.

## The launch thesis (read this first)

The product is **feature-complete** (specs 0001–0074 built; 0075–0086 + 0105/0106 built; the
weekly loop runs to a winner across seeds; the audits confirm the **Vault holds, anti-sycophancy
holds, the hidden layer + persistence are sound**). We are **discovering, not breaking.**

The bug *count* surfaced this session is high because we hunted hard (the BB-nerd audit +
real-model live-verify). But the *severity* is **concentrated in one seam**: the player-facing
**casting → premiere narration** — which is also the most visible part of the game (it is the
onboarding). The engine core is not rickety; **one soft surface that happens to be the first ten
minutes** is.

**Root cause of the recurring surprises:** every CI gate **stubs the LLM**. The product's real
behavior lives in the model↔engine seam, and that seam is the one thing CI never exercises — so
tool under-calls, narration desyncs, the inert desync guard, and cast-authoring richness all ship
*green* and only surface when a human drives a real model for ~30 minutes (SOUL lessons 17 & 19).
The strategic fix is to **make the real-model golden path an automated gate** (feature 0108, in
spec) so we stop re-discovering the same class of bug by hand.

## The acceptance bar — the golden path a real player must walk

**Definition of shippable:** a real player, on a fresh install with a real model wired, can go
**casting → first eviction** with *no dead screen, no Vault leak, no stuck beat.* Concretely, every
line below must hold in a **real-model** run (not a stubbed gate):

| # | Gate | Pass criterion | Status (2026-06-27) |
|---|------|----------------|---------------------|
| G1 | **Casting opens itself** | After setup (API key set, access enabled, settings closed), the producers send the opening message **on their own**, promptly, with no player prompt. | ⏳ #967 — fix in flight (onboarding lane); failed last live-verify |
| G2 | **Post-photo resume** | After the headshot upload, the producers acknowledge + begin the interview **automatically**, no manual "continue". | ⏳ #969 — fix in flight (onboarding lane) |
| G3 | **Casting finalizes** | One player readiness signal → `createCharacter` → season starts (`started=true, week=1, premiere`). | ✅ live-verified (#1033) |
| G4 | **Cast is richly authored** | ≥13/15 NPCs get a deep authored profile (not the deterministic floor). | ⏳ 9/15 last run — engine degradation fix in flight |
| G5 | **The game advances** | No stuck phase: HOH → noms → veto → eviction each reach the player without a manual nudge. | ✅ live-verified (F8 noms self-advance) |
| G6 | **No premature outcome leak** | The GM never narrates a result/tally the engine hasn't committed (the desync guard holds — including single-tenant `owner=None`). | ⏳ F16 guard merged (#1063); needs live re-confirm |
| G7 | **Eviction reads cleanly** | Eviction-vote card surfaces; player goodbye blocks the week roll (E34); reveal is batched, anonymized; week rolls. | ✅ live-verified (F14); F16b pacing merged (#1064) |
| G8 | **No machinery in the bubble** | Player text never contains Vault data, raw `npc:<id>`, operator asides, or reasoning tokens. | ✅ live-verified (#1047, F3) |
| G9 | **No cross-user / Vault leak** | Player + admin surfaces return zero Vault data; cross-user isolation holds. | ✅ structurally gated (dependency-cruiser + tests) |

**Launch is GO when G1–G9 all pass in a single real-model golden-path run** (which is exactly what
feature 0108's gate will assert on every PR). Today: **G3/G5/G7/G8/G9 pass; G1/G2/G4/G6 are in
flight** (the casting-seam hardening). That is the entire remaining launch-blocker set.

## What gates a launch vs. not (the triage rubric)

Apply to every open issue:

- **LAUNCH-BLOCKER** — breaks G1–G9 on the real-model golden path: a dead screen, a Vault/leak, a
  stuck beat, a broken casting/eviction step, or a cross-user violation. These, and only these,
  block ship.
- **POST-LAUNCH** — real but does not break the golden path: week-N polish, secondary surfaces,
  responsive nits that still leave the control reachable, enhancements, calibration tuning,
  refactor-roadmap items (R1–R7). Ship without them; fix on a fast-follow.
- **PARKED** — needs a product decision or external input, not more agents: the Glass cluster, the
  HIG-audit set, the PO-review enhancements, and the real-host/deploy items (#0010 Proxmox smoke).
  Surface to the owner; do not spend agents until decided.

**Discipline:** new bugs found after this line is drawn are triaged into one of the three buckets
on sight. Only the LAUNCH-BLOCKER bucket may delay ship. The ~80 open issues are
**overwhelmingly post-launch/parked** — they are not a launch backlog.

## The hardening tracks (in flight as of 2026-06-27)

1. **Real-model golden-path gate (feature 0108, spec in progress).** Record one real run; replay it
   deterministically in CI to assert G1–G9 on every PR (key-free); nightly real-model smoke to
   catch prompt drift. *This is the move that makes "ship soon" safe* — it converts the manual
   30-minute live-verify into a repeatable gate.
2. **Casting → premiere P0 hardening.** G1 (#967 opener), G2 (#969 resume), G4 (cast authoring:
   the FE retry landed 3/15→9/15; the engine `recordCastProfile` degradation refusal is the
   remaining loss), G6 (F16 guard live re-confirm).
3. **Season-start concurrency.** The background write-backs racing premiere mutations (the
   degradation refusals) is architectural — reconcile-and-retry (the 0081 pattern) or serialize
   against premiere. Kills a whole bug class, not one instance.
